Lesson 0004 · AI agent skills for GitHub Copilot

Provider philosophies compared

You have 138 skills installed from four providers. They are not four piles of the same thing: each provider is a different answer to one question — who owns the process while the agent works? This lesson gives you the four answers, the places they collide, and a routing map.

After this lesson you can take any real task and name which provider's flow fits it and why — and you know the four collision domains where two or more providers claim the same job, so you route by name instead of trusting auto-invocation.
01 · Process ownership 02 · Provider portraits 03 · Collisions 04 · Routing map Practice

1 · One question, four answers

Each provider makes a different bet about who directs the work. First compare how skills route a task. Then add the separate question humanlayer answers: how does the work survive a fresh context window?

01 · Start with the endpoints

You choose, or a mandate routes

mattpocock leaves you in charge of the process. At the other end, pstack's SessionStart hook injects a mandate to use poteto-mode, which routes qualifying tasks to playbooks.

02 · Add an advisory router

A phase map helps you choose

addyosmani supplies standalone discipline playbooks plus using-agent-skills. That workflow driver suggests a phase map, rather than injecting pstack's session-start mandate.

03 · Add continuity between sessions

Documents carry the next phase

humanlayer's rpi is not another point on that axis. It writes research, design, and outline artifacts to disk. Each phase uses a fresh context window and reads those documents.

The lesson's inventory snapshot counts 25 + 67 + 7 + 39 SKILL.md files on disk. These are not live counts. pstack also ships one under grok\, another runtime's slice.

4 · The routing map

Start with the job, then follow its route to a provider. These are starting points, not exclusive assignments. The reference keeps the compact lookup table.

  • Debug, harden, optimize, or ship

    →

    addyosmaniThe matching discipline playbook

    A self-contained workflow with verification gates. No subagent fan-out required.

  • Compare contested designs

    →

    pstackpoteto-mode, then architect or arena

    Competing candidates and cross-model judging. Reserve the extra token cost for work that warrants it.

  • Build across days or context windows

    →

    humanlayerrpi

    Reviewed documents preserve decisions. Each fresh phase reads them back.

  • Write specs, tickets, PR prose, or lessons

    →

    mattpocockto-spec, grilling, pr, or teach

    Small composable tools. You keep control of the sequence.

  • Apply one course correction

    →

    pstackA principle-* leaf

    One rule you can apply inside another workflow.

  • Explain something visually

    →

    humanlayershow-me

    A focused diagram or sketch beside the explanation.

Notice what the map does not say: it never routes by provider loyalty. mattpocock for prose and pstack for rigor and addyosmani for discipline is the intended end state — curation, not a winner.

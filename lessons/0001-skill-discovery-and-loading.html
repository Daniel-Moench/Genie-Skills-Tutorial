Lesson 0001 · AI agent skills for GitHub Copilot

How Copilot discovers and loads skills

You know what a skill is. This lesson is about the machinery around it: how a SKILL.md on disk ends up influencing a session, and why only part of it enters the model's context — and when.

After this lesson you can trace any skill in your session back to a file on disk, and predict which of the three invocation paths will make it fire.

1 · Three discovery tiers

Copilot looks for skills in three kinds of places (official docs):

TierLocationScope
Personal folders ~\.copilot\skills\ (also honours ~\.agents\skills\, ~\.claude\skills\) You, every project
Repository folders .github\skills\ (also .agents\skills\, .claude\skills\) Everyone in that repo
Installed plugins ~\.copilot\installed-plugins\<marketplace>\<plugin>\skills\ You, every project

All four of your providers arrived through tier 3. On your machine:

~\.copilot\installed-plugins\
├── addy-agent-skills\agent-skills\skills\      25 skills
├── mattpocock\mattpocock-skills\skills\        40 skills
├── pstack-claude\pstack\skills\               ~70 skills
├── skills\  (= humanlayer, one folder/skill)    7 skills
└── _direct\ (single skill installs)             1 skill

Two files wire plugins up: ~\.copilot\config.json records the marketplace (e.g. the GitHub repo michael-denyer/pstack-claude), and ~\.copilot\settings.json records that the plugin is enabled ("pstack@pstack-claude": true). Because all of this is user-level, the same inventory follows you into VSCode, IntelliJ, the Desktop App, and the CLI.

2 · From disk to prompt: progressive disclosure

Discovery does not mean 70 pstack skill bodies get pasted into every session. At session start, only each skill's name + description frontmatter is listed in the system prompt (an available skills index). The body of SKILL.md — the actual instructions — enters the context only when the skill is invoked. That's the whole trick that makes ~140 installed skills affordable: cheap index always, expensive body on demand.

One wrinkle you can verify on your own machine: when a plugin is very large, Copilot lists only part of its skills in the prompt index. The unlisted rest is still installed and still loads — but only when named exactly (by you, or by another skill).

3 · Three ways a skill fires

PathWho triggersExample
Slash command You, explicitly /teach built this workspace
Description match The model, automatically You say “review this diff” → a skill whose description says “Use when reviewing code…” is loaded first
Named by another skill A skill or instruction file pstack's poteto-mode routes to tdd, architect, … by name

Consequence: the description field is not documentation — it is the trigger surface. That's why good providers write them as “Use when…” rules. When you later curate your set, badly written descriptions are a legitimate reason to drop a skill: they misfire.

4 · Collisions

You currently have three TDD skills installed: test-driven-development (addyosmani), tdd (mattpocock), and tdd (pstack). Their descriptions overlap, so on a “write tests first” task the model must pick one — and which one wins is not guaranteed. Plugins namespace their skills (pstack:tdd vs mattpocock-skills:tdd), which lets you disambiguate explicitly, but automatic description-matching remains a lottery between overlapping providers. This is the core problem your final curation lesson will solve: keep one winner per job, or install a router (pstack's poteto-mode is exactly that — more in lesson 2).

  1. Count your real inventory: 
    Get-ChildItem ~\.copilot\installed-plugins -Recurse -Filter SKILL.md | Measure-Object
  2. Open one unfamiliar SKILL.md (pick from skills\rpi\ in the humanlayer folder) and read only the frontmatter. Predict: what user sentence would auto-trigger it?
  3. Prove on-demand loading: in a fresh Copilot session, invoke a pstack skill that is not listed in your prompt (e.g. poteto-help) by name. It loads anyway — tier-3 discovery plus name-addressing at work.
